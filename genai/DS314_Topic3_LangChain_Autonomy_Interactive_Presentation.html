Spotting the AIMessage Trap

A classic exam question analyzing broken LangChain code snippets.

  • Broken Snippet:
    res = llm.invoke("Hi")
    print(res.upper())
  • The Bug: res is an AIMessage object, NOT a Python string! Calling .upper() triggers AttributeError.
  • Why it happens: AIMessage is a container encapsulating content, metadata, and tool calls.

Weights are frozen. An API call is an isolated mathematical evaluation. The model retains no residual internal cache from previous turns.

Single-Turn Collapse: If User Turn 1 is "Who was Abraham Lincoln?" and Turn 2 is "When was he born?", the model sees only Turn 2 and cannot resolve the referent of "he".

THE ILLUSION OF MEMORY

Pre-pending Conversation History

CLICK TO FLIP ↻

App-Level State: Chatbots appear to remember because the application stores message history and injects previous turns back into the prompt on every turn.

Token Limits & Sliding Windows

CLICK TO FLIP ↻

History Bloat: As turns accumulate, prompt token counts surge. Production apps use sliding windows (last 6 turns) or summary memory.

THE DOCSTRING CONTRACT

Docstrings as Functional API Schemas

Why docstrings are NOT optional comments

SCHEMA SPECIFICATION

The Critical Role of Python Docstrings

The model cannot see Python code; it only reads the docstring.

  • The Model Perspective: The agent does NOT inspect Python bytecode; it reads the docstring!
  • The Vague Docstring Trap: If the docstring is """checks things""", the model will not understand when to call it.
  • Best Practice: Explicitly state the tool's purpose, expected input format, and output payload in the docstring.
